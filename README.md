# AI-SDLC-SDD: Spec-Driven Development с поддержкой Threat Modeling

Репозиторий проекта **AI-SDLC-SDD**, посвященного методологии спецификационно-ориентированной разработки (Spec-Driven Development, SDD) с использованием искусственного интеллекта. 

Проект предоставляет системный промпт для AI-ассистента (роль: системный аналитик и архитектор), который помогает генерировать полный пакет проектной документации по стандарту **OpenSpec v1.x**, интегрируя обязательный этап **Threat Modeling** и опциональную поддержку **ГОСТ 34/19**.

## 🎯 Назначение

Файл `openspec-prompt.md` содержит жесткий регламент (пайплайн) для LLM, который позволяет:
*   Генерировать артефакты строго последовательно: `proposal → specs → design → threat-model → adr → api-contract → test-specs → tasks → apply`.
*   Автоматически выбирать методологию Threat Modeling (STRIDE, OWASP Top 10 for LLM, LINDDUN и др.) в зависимости от входных данных (`security_context`).
*   Формировать матрицу трассируемости (Traceability Matrix) и проверять артефакты на соответствие Definition of Done.
*   (Опционально) Генерировать документы по ГОСТ 34/19 (ТЗ, ПМИ, пояснительные записки) на основе артефактов OpenSpec.

## 📂 Структура репозитория

*   **`openspec-prompt.md`** — основной системный промпт. Содержит роль, входные параметры (feature, constraints, security_context), правила генерации каждого артефакта, лимиты объемов и требования к визуализации (Mermaid).
*   **`README.md`** — описание проекта (этот файл).
*   *(Опционально)* `context.md` — файл, который создается в процессе работы для сохранения состояния между шагами генерации.

## 🚀 Как использовать

1.  **Подготовка:** Откройте диалог с LLM (ChatGPT, Claude, YandexGPT и т.д.), которая поддерживает длинный контекст и генерацию Markdown/Mermaid.
2.  **Загрузка промпта:** Передайте модели содержимое файла `openspec-prompt.md` в качестве системной инструкции или первого сообщения.
3.  **Ввод данных:** Модель запросит обязательные параметры (название фичи, описание, домен, `security_context`). Заполните их.
4.  **Генерация:** Модель начнет пошаговую генерацию артефактов. После каждого шага она будет ждать подтверждения (`y/n`), чтобы вы могли проверить результат и скорректировать курс.
5.  **Результат:** Вы получите набор файлов (`.md`, `.yaml`), которые можно сохранить в репозиторий проекта.

## 🛡️ Особенности Threat Modeling

Промпт содержит встроенную логику выбора методологии анализа угроз:
*   Если проект использует LLM/AI (RAG, агенты) — выбирается **OWASP Top 10 for LLM** или гибридный **STRIDE + OWASP LLM**.
*   Если ключевой фактор — персональные данные (GDPR, 152-ФЗ) — выбирается **LINDDUN**.
*   Для классических API без AI — **STRIDE**.
*   Пропуск этапа `threat-model` заблокирован (кроме случая минимальной жизнеспособной модели).

## 📑 Поддержка ГОСТ (Опционально)

Если при инициализации указать `gost_compliance: true`, ассистент будет параллельно с OpenSpec-артефактами генерировать документы по ГОСТ 34/19 (например, ТЗ по ГОСТ 34.602-89 или ПМИ по ГОСТ 34.603-92), сохраняя трассируемость между ними.
